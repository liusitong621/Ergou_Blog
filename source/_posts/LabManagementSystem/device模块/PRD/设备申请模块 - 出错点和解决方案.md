# 二、Pydantic 模型问题

## 2.1 默认值问题：default=None vs default=""

**核心原则：**&#x7F16;辑接口的字段要用 `default=None`，而非 `default=""` 或 `default=0`

| 写法                                     | 含义         | 适用场景          |
| -------------------------------------- | ---------- | ------------- |
| `name: str = Field(..., min_length=1)` | 必填字段，不传报错  | 创建接口的必填项      |
| `name: str = Field(default="")`        | 可选，默认空字符串  | 创建接口的可选项      |
| `name: Optional[str] = None`           | 可选，默认 None | **编辑接口的所有字段** |

**为什么编辑接口要用 default=None？**

编辑时需要区分「用户传了空字符串」和「用户没传」：

- `default=""`：无法区分，前端不传时默认为空字符串，会覆盖原有值
- `default=None`：可以判断 `if body.name is not None`，只更新传了的字段

## 2.2 类型声明：Optional[int] vs int

**错误写法：**

```python
totalQuantity: int = Field(default=None)  # ❌ 类型是 int，默认值是 None
```

**正确写法：**

```python
totalQuantity: Optional[int] = Field(default=None)  # ✅ 明确允许 None
```

**问题原因：**&#x867D;然写了 `default=None`，但类型声明是 `int`，Pydantic 会把"没传"的字段当作需要验证的 `int` 类型，可能产生隐式转换。

## 3.1 查询对象创建

**错误写法：**


**正确写法：**


## 3.2 链式调用顺序

**正确顺序：**


## 3.3 重复校验（编辑时排除自身）

**创建时的校验（不排除）：**

```python

```

**编辑时的校验（排除自身）：**

```python
exist = db.query(Device).filter(
    Device.serial_number == new_serial,
    Device.id != device_id  # 关键：排除自己
).first()
```

# 五、逻辑错误

## 5.1 可用数量为 0 时的误判

**错误写法：**

```python
if not avail or avail is None:  # ❌ 当 avail=0 时，not avail 为 True
    avail = body.totalQuantity
```

**问题场景：**&#x7528;户明确传 `availableQuantity: 0`（表示无库存），会被错误地改为 `totalQuantity`。

**正确写法：**

```python
if avail is None:  # ✅ 只判断是否为 None
    avail = body.totalQuantity
```

## 5.2 db.commit() 和 db.refresh() 顺序

**错误顺序：**

```python

```

**正确顺序：**

```python
db.commit()      # ✅ 先提交到数据库
db.refresh(row)  # 再从数据库刷新对象
```

# 十一、测试过程中遇到的问题

## 11.1 Query 参数类型不匹配

**错误信息：**&#x49;nput should be a valid integer, unable to parse string as an integer

**错误信息：**&#x49;nput should be a valid date or datetime, input is too short

**问题原因：**&#x51;uery 参数类型定义错误：

```python

data_from: datetime.date = Query(default="")          # Query 不能直接接收 datetime.date
```

**解决方法：**

```python
# ✅ 正确
status: Optional[int] = Query(default=None, ge=0, le=3)
date_from: Optional[str] = Query(default=None)        # 先用 str 接收，再在内部转换
```

## 11.2 SQLAlchemy 过滤条件缺少模型前缀

**错误信息：**&#x4E;ameError: name "start_date" is not defined

**问题原因：**&#x53;QLAlchemy 查询必须使用 `Model.field` 的形式：

```python
# ❌ 错误
query = query.filter(start_date >= date_from)        # 缺少模型前缀

# ✅ 正确
query = query.filter(DeviceBooking.start_date >= date_from_obj)  # 必须指定模型
```

## 11.3 日期字符串缺少转换

**错误信息：**&#x54;ypeError: can only compare datetime.date to datetime.date

**问题原因：**&#x51;uery 参数传入的是字符串，需要转为 `date` 对象才能和数据库字段比较：

```python
# ❌ 错误
query = query.filter(DeviceBooking.start_date >= date_from)  # date_from 是 str

# ✅ 正确
date_from_obj = datetime.datetime.strptime(date_from, "%Y-%m-%d").date()
query = query.filter(DeviceBooking.start_date >= date_from_obj)
```

## 11.4 日期格式错误缺少异常处理

**错误信息：**&#x56;alueError: time data "2026/07/17" does not match format "%Y-%m-%d"

**问题原因：**&#x7528;户传入错误的日期格式（如用斜杠），没有捕获异常：

```python
# ❌ 错误
date_from_obj = datetime.datetime.strptime(date_from, "%Y-%m-%d").date()  # 可能抛出 ValueError

# ✅ 正确（添加 try-except）
try:
    date_from_obj = datetime.datetime.strptime(date_from, "%Y-%m-%d").date()
    query = query.filter(DeviceBooking.start_date >= date_from_obj)
except ValueError:
    raise HTTPException(status_code=400, detail="日期格式错误，请使用 YYYY-MM-DD")
```

## 11.5 参数名拼写错误

**错误信息：**&#x4E;ameError: name "data_from" is not defined

**问题原因：**&#x53C2;数名和变量名不一致：

```python

...

    ...

# ✅ 正确
date_from: Optional[str] = Query(default=None)  # 参数名是 date_from
...
if date_from:                                    # 使用正确的名字
```
