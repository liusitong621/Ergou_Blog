## 第 1 章 数据库：补全 `device_bookings` 表字段

### 1\.1 为什么要改表

用户端申请表单要填：学号、姓名、班级、专业、电话、教师、事由等。
当前 `device_bookings` 表只有 `user_name`，不够用。
审核还需要 `admin_remark`（管理员备注）和 `reject_reason`（拒绝原因），参照 `appointments` 表。

### 1\.2 需要新增的字段

打开 `backend/app/models/device_booking.py`，在 `DeviceBooking` 类中**增加**以下列定义（具体 Column 写法参照 `appointment.py`）：

|**字段名**|**类型建议**|**说明**|
|---|---|---|
|device\_name|String\(128\)|设备名称|
|serial\_number|String\(64\)|设备编号|
|student\_id|String\(64\)|学号|
|class\_name|String\(64\)|班级|
|major|String\(64\)|专业|
|phone|String\(32\)|电话|
|teacher\_id|String\(64\)|指导教师 ID|
|teacher\_name|String\(64\)|指导教师姓名|
|admin\_remark|Text|管理员备注|
|reject\_reason|Text|拒绝原因|

同时确认：`user_name` 用来存申请人姓名（对应表单 `name` 字段）。下面举几个例子说明代码具体如何写：橙色高亮的代码就是新增代码。例如根据表格新增device\_name，类型是String\(128\)，说明是设备名称，所以增加的代码就是device\_name = Column\(String\(128\), nullable=False, comment="设备名字"\)

```Python
"""设备申请表/设备借用工单表模型"""
from sqlalchemy import Column, Integer, String, Text, SmallInteger, DateTime, Date
from sqlalchemy.sql import func

from app.core.database import Base


class DeviceBooking(Base):
    __tablename__ = "device_bookings"

    id = Column(Integer, primary_key=True, autoincrement=True)
    device_id = Column(Integer, nullable=False, comment="关联设备id")
    device_name = Column(String(128), nullable=False, comment="设备名字")
    serial_number = Column(String(64), nullable=True, comment="设备序列号")
    quantity = Column(Integer, nullable=False, default=1, comment="申请借用数量")
    start_date = Column(Date, nullable=False, comment="开始日期")
    end_date = Column(Date, nullable=False, comment="结束日期")
    reason = Column(Text, nullable=False, comment="借用/使用原因")
    special_requirement = Column(Text, nullable=True, comment="申请特殊需要，可为空")
    user_id = Column(Integer, nullable=True, comment="用户ID")
    user_name = Column(String(64), nullable=False, default="", comment="用户姓名")
    # 0: 待审核 1: 已通过 2: 已拒绝 3: 已取消
    status = Column(SmallInteger, nullable=False, default=0, comment="工单状态: 0待审核 1已通过 2已拒绝 3已取消")
    created_at = Column(DateTime(timezone=True), server_default=func.now(), comment="记录创建时间")
    openid = Column(String(128), nullable=False, default="", comment="用户openid")
    class_name = Column(String(64), nullable=False, comment="班级")
    major = Column(String(64), nullable=False, comment="专业")
    phone = Column(String(32), nullable=False, comment="手机号")
    teacher_id = Column(String(64), nullable=True, comment="教师ID")
    teacher_name = Column(String(64), nullable=False, comment="教室名字")
    admin_remark = Column(Text, nullable=True, comment="审核员的评论")
    reject_reason = Column(Text, nullable=True, comment="审核员输入的拒绝原因")
```

### 1\.3 让数据库真正拥有这些列

### 2\.4 实现 GET /devices 接口（列表）


### 2\.8 管理端「下架」怎么做（P0 不做 DELETE）\-\- 先不用做

PRD 建议用**软下架**，不物理删除记录：

- 把 `status` 改为 `2`（报废），或

- 把 `available_quantity` 改为 `0`

用户端 `scope=public` 时自然看不到或显示不可借。

如果一定要做 DELETE 接口（可选）：

```Plaintext
DELETE /devices/{id}
    检查 device_bookings 有没有该 device_id 且 status 为 0 或 1 的记录
    如果有 → 400 "存在进行中申请，不能删除"
    否则 db.delete(row); commit
```

### 4\.3 实现 POST /device\-bookings

伪代码：

```Plaintext
POST /device-bookings

函数 create_device_booking(body, db):
    # 1. 查设备
    device = db.query(Device).filter(id == body.deviceId).first()
    如果不存在 → 404 "设备不存在"

    # 2. 可借校验
    如果 device.status != 0 → 400 "设备当前不可借"
    如果 device.available_quantity < body.quantity → 400 "可借数量不足"

    # 3. 日期校验
    如果 body.borrowEnd < body.borrowStart → 400 "归还日期不能早于开始日期"

    # 4. 必填校验
    如果 body.phone 为空 → 400
    如果 body.reason 为空 → 400

    # 5. 创建申请记录
    row = DeviceBooking(
        device_id = device.id,
        device_name = device.name,
        serial_number = device.serial_number,
        quantity = body.quantity,
        start_date = 解析 body.borrowStart 为 Date,
        end_date = 解析 body.borrowEnd 为 Date,
        reason = body.reason.strip(),
        student_id = body.studentId.strip(),
        user_name = body.name.strip(),
        class_name = body.className.strip(),
        major = body.major.strip(),
        phone = body.phone.strip(),
        teacher_id = body.teacherId.strip(),
        teacher_name = body.teacherName.strip(),
        status = 0,
        admin_remark = "",
        reject_reason = "",
        openid = "",
        user_id = None,
    )
    db.add(row)
    db.commit()
    db.refresh(row)
    返回 { ok: true, id: row.id }
```

说明：

- `start_date` / `end_date` 在模型里是 `Date` 类型，需要把字符串转成 `date` 对象（可用 `datetime.strptime` 或 `date.fromisoformat`）。

- **P0 不扣减** `available_quantity`，只在提交时校验够用即可。

```Plaintext
        query = query.filter(start_date >= date_from)
    如果 date_to 有值:
        query = query.filter(start_date <= date_to)

    total = query.count()
    rows = query.order_by(id.desc()).offset(...).limit(...).all()

    返回 {
        data: [ 每条记录转成字典，字段名用前端习惯的驼峰或下划线，与 appointments 保持一致 ],
        pagination: {...}
    }
```

### 5\.2 实现 PATCH /device\-bookings/\{id\}/review（审核）

伪代码（与 `review_appointment` 几乎相同）：

```Plaintext
类 DeviceBookingReviewBody:
    action: 字符串，"approve" 或 "reject"
    adminRemark: 字符串，默认空
    rejectReason: 字符串，默认空

PATCH /device-bookings/{appointment_id}/review

    row = 按 id 查 DeviceBooking，不存在 → 404

    action = body.action 转小写

    如果 action == "approve":
        row.status = 1
        row.admin_remark = body.adminRemark.strip()
        row.reject_reason = ""
    否则如果 action == "reject":
        如果 body.rejectReason 为空 → 400 "拒绝时必须填写拒绝原因"
        row.status = 2
        row.reject_reason = body.rejectReason.strip()
    否则:
        400 "action 仅支持 approve/reject"

    db.commit()
    返回 { ok: true, data: { id, status, admin_remark, reject_reason } }
```

## 附录 A 概念速查

|**概念**|**在本项目里干什么**|
|---|---|
|`APIRouter`|把一组 URL 接口组织在一个文件里|
|`Depends(get_db)`|每个请求自动拿一个数据库连接，用完关闭|
|`BaseModel`|定义请求/响应 JSON 的格式和校验规则|
|`db.add(row)`|把新对象放入待提交队列|
|`db.commit()`|真正写入数据库|
|`db.refresh(row)`|提交后刷新对象（拿到数据库生成的 id 等）|
|`HTTPException(400, detail="...")`|告诉前端请求不合法|



## 附录 B 常见错误排查表

|**现象**|**排查顺序**|
|---|---|
|Swagger 看不到新接口<br>|`main.py` 是否 import 并 `include_router`；是否重启后端|
|404 Not Found|URL 前缀是否为 `/api/devices`；router 的 prefix 是否写对|
|422 Unprocessable|请求 JSON 字段名是否与 Pydantic 一致（驼峰 vs 下划线）|
|500 Internal Server Error|看终端完整报错；多半是缺列或日期格式转换失败|
|列表为空|是否先用 POST 录入了设备；public scope 是否过滤掉了维修/报废|
|申请成功但列表看不到|GET 列表的排序/分页；是否查错表|
